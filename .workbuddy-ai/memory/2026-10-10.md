# 2026-10-10

## AI Resume Generator —— 从零搭建（首日）

**目标**：基于岗位要求自动生成简历的应用。用户粘贴 JobStreet/Indeed 的 JD 文本，
结合固定资料库，用 LLM 生成针对性简历；任务化并发；版式动态；HTML 承载可编辑可导出 PDF。

### 技术栈决策（已定，后续沿用）
- 后端：FastAPI + SQLModel + SQLite(WAL) + asyncio 队列 worker 池
- 前端：原生 ES Module SPA（无构建工具），Ark UI 设计语言 `ark` 家族 + `moderate` 深度
- LLM：OpenAI 兼容 `/chat/completions`，httpx 异步；**无 key 时降级到 `mock.py` 启发式**
- PDF：浏览器打印（矢量文字），不做服务端渲染
- 验证：`backend/tests/ui_check.py` 用 Playwright + `channel="msedge"`（复用系统 Edge，免下载 Chromium）

### 核心设计
- **模型只输出 resume spec JSON，HTML 由确定性 Jinja2 渲染器产出**（安全性 + 可编辑 + 可零成本重排版）
- **HTML 是简历唯一真相来源**；spec 仅作生成快照，用于「版式」页重渲染
- 进度阶段：10% 载入资料 → 25% 解析岗位 → 60% 生成内容 → 85% 渲染 → 100% 落库
- WebSocket `/ws/tasks` 实时外推 `task_progress` / `task_updated`

### 踩过的坑（重要，别重复踩）
1. **FastAPI `status_code=204` 的路由不能有返回体**：`-> None` 会触发
   `AssertionError: Status code 204 must not have a response body`。
   解法：`response_class=Response` 且 `return Response(status_code=204)`。
2. **`Content-Disposition` 文件名含中文会报 `UnicodeEncodeError: 'latin-1'`**（starlette 用 latin-1 编码 header）。
   解法：RFC 5987 —— `filename="resume.html"; filename*=UTF-8''<urlquote(name)>`。
3. 简历 CSS 含 `:root` / `@page` 全局选择器，**不能直接塞进主文档做 contenteditable**（会污染应用样式）。
   解法：用 `iframe.srcdoc` + `contentDocument.designMode='on'` 做样式隔离。
4. 无 key 时别让前端报错——降级模式要在顶栏明示（`LLM // 降级模式`）。

### 目录约定
- 后端在 `backend/`，入口 `app.main:app`，启动用 `--app-dir backend`
- 数据库落在 `data/app.db`，测试截图在 `backend/tests/shots/`（已 gitignore）
- 前端静态资源 `backend/app/static/`，由 FastAPI 挂载 `/static` + `/` 返回 index.html

端到端已验证通过：`smoke.py`（后端全链路）✅ / `ui_check.py`（13 张截图，0 控制台错误）✅

## 第二轮：架构评审 + 缺陷审计 + 四批修复（同日）

用 4 人团队（架构师/QA/工程师/终验QA）做了完整审计与修复闭环。

### 审计发现并已修复的缺陷（共 13 项）
**P0（严重）**
1. 删除已生成简历的任务 → 500（`JobTask.resume_id` ↔ `Resume.task_id` 双向外键）。
   解法：`delete_task(cascade=False)` 默认 409，`?cascade=true` 才级联删。
2. 取消运行中任务无效（`pipeline.run_task` 从不检查取消标志）。
   解法：注入 `should_cancel` 回调（**避免 pipeline↔scheduler 循环导入**），抛 `TaskCancelled`。
3. 运行时改 worker 数 → 任务永久卡 running。解法：`_restart_workers` 取消前先收集 `_running` 重新入队。
4. 简历标题 XSS（`build_preview_document` f-string 拼 `<title>`）。解法：`html.escape`。
5. **未填资料直接建任务 → `'NoneType' object has no attribute 'name'`**（新用户首次路径）。
   解法：`_profile_to_dict(None) -> {}` + `_is_profile_empty()` + 可读中文报错。

**P1（中）**
6. 5 种版式中 `timeline`/`compact-grid` 无任何 CSS → 与单栏完全相同。解法：补专属 CSS。
7. 未定义 section type → 静默空章节。解法：渲染器加兜底 + 保留 `data-section-type`。
8. 非法 layout/theme 被静默接受。解法：白名单 → 400（**刻意不用 Literal→422**，400 带可读提示对用户更友好）。
9. 前端缺「删除简历」入口。解法：补按钮 + 确认文案。
10. 删除简历后任务仍 `succeeded` 但 `resume_id=None`。解法：采用「任务与简历一对一单元」语义，删简历同时删任务。
11. **AI 编辑产物信任边界**（存储型 XSS 面）。见下方「最大教训」。
12. 重排队/失败时 `progress` 未重置（4 处：`_recover`/`_restart_workers`/自动重试/终态失败），
    且对应 WebSocket 广播未带 `progress` 字段 → 前端卡片一直显示旧值。解法：4 处补 `t.progress=0` + 广播补 `"progress": 0`。
13. 重复入队竞态（`_handle` 非原子读改写）。解法：条件 UPDATE（`WHERE status='queued'`）+ `rowcount==0` 早退。

### 最大教训：手写正则净化器是反模式
我最初让工程师手写正则 sanitizer，QA 用无头浏览器实测出 **5 条绕过**且端到端可达：
- `<img/onerror=...>`（事件属性正则要求 `on*` 前是空白，`/` 分隔就漏）
- `<svg/onload=...>`、无引号变体
- `jav&#x61;script:` / `&#106;avascript:`（只替换 3 个写死实体，不解码通用实体）

**正确做法**：换 `nh3`（Rust ammonia 绑定，`nh3==0.3.7`，Windows/Py3.13 有预编译 wheel）
+ **加严格 CSP** 做架构级兜底（`default-src 'none'; style-src 'unsafe-inline'; img-src data: https:`）。
CSP 这层不依赖净化器正确性——即使净化被绕过，脚本也执行不了。

**nh3 两个坑**：
- `clean_content_tags` 里只能放 `script`，放 `style` 会 panic（`style` 同时在 `tags` 里）
- `removed` 标志不能用 `clean != html` 判断（nh3 会补 `rel="noopener noreferrer"`、调属性顺序 → 误报）；
  要用独立的 `_looks_dangerous()` 探测器，它只驱动提示文案、不承担安全职责

### 我自己的验证方法（值得复用）
不看被审者自己的测试，独立重写验证：
- **接口返回体 vs DB 实际状态对比** —— 只有这种方式才抓到了「progress 未重置」（工程师 74 项断言、QA 两轮都漏了）
- **采样状态变迁**（每 0.2s 打一次）而不是只看终态
- **浏览器渲染截图指纹 / 布局几何量测** 验证版式差异，而不是结构哈希（哈希会被归一化骗过）
- 踩过的探针陷阱：`getBoundingClientRect().left` 不反映 `padding-left`；console 列表跨页面累加；
  用 `PUT` 覆盖内容后再断言原渲染器的 CSS 生效

## 第三轮：供应商预设模型配置（同日）

用户诉求：不要让用户手填 Base URL，改成**下拉选供应商 → 自动填 URL 与模型 → 只填 API Key → 右侧「测试连接」按钮**。
参考了 DeepSeek 官方文档与 WorkBuddy 的模型配置文档（后者的理念正是「提供商自动填充 URL/模型列表，仅需补 API Key」）。

### 从官方文档核实的事实（勿凭印象写）
- DeepSeek Base URL：`https://api.deepseek.com`（OpenAI 兼容，`/chat/completions` 直接拼在后面）
- DeepSeek 模型：`deepseek-flash`、`deepseek-v4-pro`。**旧名 `deepseek-v4-flash` 等仍被接受但对应模型已退役**，不要写进预设
- 列模型端点：`GET https://api.deepseek.com/models`，`Authorization: Bearer <TOKEN>`，返回 `data[].id`
- **`/models` 需要鉴权** → 200 = key 有效、401 = 无效，正好用来做「测试连接」
- Key 申请：`https://platform.deepseek.com/api_keys`

### 实现要点
- 新增 `app/providers.py`：10 个供应商预设（DeepSeek 默认排第一）+ `is_local_url()` + `match_provider_by_base_url()`
- 新增 `GET /api/settings/providers`、`POST /api/settings/llm/test`
- 测试连接：先打 `/models`；404/405 时**回退发一次最小 `/chat/completions`** 探测
- 前端：供应商横排 chip（比 `<select>` 更直观）、Base URL 只读展示（仅 custom 可编辑）、
  测试结果用**行内提示**而非 toast（toast 三秒就没了，用户回头想确认看不到）、
  模型下拉带「＋ 自定义模型名」兜底（预设模型名会随服务商版本变化）

### 本轮修掉的缺陷
1. **`provider_id` 陈旧**：`set_runtime_config` 会跳过值为 None 的键，所以 PUT 不带 provider_id 时
   改不了它，而 base_url 已经变了 → 配置自相矛盾（弹窗高亮错供应商）。
   修：`update_llm_settings` 里当 provider_id 为空且 base_url 不为 None 时，按 base_url 反查。
   **工程师的回归漏了它，因为那条用例从「库里没有 provider_id」起步；真实用户先配一次就会写进库。**
2. **代理劫持本地 LLM**：`httpx.AsyncClient` 默认 `trust_env=True` 会读 `HTTP_PROXY`，
   导致 Ollama（`http://localhost:11434/v1`）在设了代理的机器上完全不可用。
   修：`is_local_url()` 命中本机地址时 `trust_env=False`，外部地址仍 `True`（不全局关闭，保住企业代理能力）。

### 环境坑（本机特有，务必记住）
**本机设了 `http_proxy`，代理会拦截 localhost 请求返回 502。**
- curl 要加 `--noproxy '*'`
- httpx 要 `trust_env=False` 或设 `NO_PROXY=localhost,127.0.0.1`
- 起服务做本地验证时要给服务进程也带上 `NO_PROXY`
- Playwright `launch()` 首跑偶发被杀，加 `--no-sandbox --disable-gpu --no-proxy-server` 后稳定

### 我自己的验证方法（本轮又验证了一次）
- **「保存成功」≠「生效」**：起本地假 LLM 服务，看它**是否真的收到请求**（含 Authorization 与 model 字段）。
  这比断言接口返回 200 强得多。
- **故意让服务端进程带代理环境变量**，再验证应用能否连上本地假服务 —— 这才是绕过逻辑的真实证明。
- 本轮我又踩了两个探针坑：断言「预设列表不含 api_key」被 `key_url` 里的字样误伤；
  重定向测试压根没在假服务里实现重定向；`hasattr(client, "uses_proxy")` 断言平凡通过（属性不存在）。
  **断言写得太宽松等于没写。**

## 第四轮：一键启动脚本

新增三个文件：`start.py`（主逻辑，跨平台）、`start.bat`（Windows 双击）、`start.sh`（macOS/Linux）。

**启动器做的事**：建虚拟环境 → 装依赖 → 挑可用端口 → 起服务 → 等健康检查通过后开浏览器。
- **依赖用戳记（`.venv/.deps-stamp`）记录 requirements.txt 的 sha256**，没变就跳过安装，避免每次启动都重装。
- **若当前解释器不是 `.venv` 里的，用 `os.execv` 重新执行自己**，保证依赖装进隔离环境。
- **端口被本应用占用时不重复起服务**，直接开浏览器（通过 `/api/health` 判断是不是自己）。
- **自动为子进程设置 `NO_PROXY=localhost,127.0.0.1,::1,0.0.0.0`** —— 直接解决第三轮发现的代理拦截 localhost 问题。
- 参数：`--port` / `--host` / `--no-browser` / `--reload` / `--reinstall`。

**顺带修的 bug**：`main.py` 的 lifespan 日志用 `settings.port`（配置默认值）打印"就绪 -> URL"，
换端口启动时会打印**错误端口**（实测 8021 却显示 8000）。修法：启动器注入 `APP_PORT` 环境变量，
`main.py` 优先读它，回退到 `settings.port`。

**`.bat` 的注意点**：内容保持纯 ASCII（避免编码问题），用 `%~dp0` 取脚本目录而不是硬编码路径
（项目路径含中文，硬编码会出问题）。`chcp 65001` 设 UTF-8 以便显示中文输出。

### 用户实测报错 & 修复（重要教训）
用户用 `python start.py` 报：
```
D:\学习目标_笔记\2.: can't open file '...\AI Resume Generator\智\计算机\自学\9'
```
**根因**：`ensure_venv()` 里用 `os.execv` 重新执行自己。**Windows 上的 `os.execv` 不会正确转义含空格的路径参数**，
而项目路径里有 `2. 智` 这样的空格，参数被拆坏后拼成畸形路径。
**修法**：改用 `subprocess.run([...], cwd=ROOT)` 传参数列表（内部走 `list2cmdline`，会正确加引号），再 `sys.exit(returncode)`。
同时加了 `_RESUME_GENERATOR_REEXEC` 环境变量防止无限重执行，并用 `os.path.normcase` 比较解释器路径（兼容 Windows 大小写）。
另把横幅移到 `ensure_venv()` 之后，避免重执行时打印两次。

**我的测试方法错了（教训）**：之前一直用 `./.venv/Scripts/python.exe start.py` 测试，
而这条路径下 `running_in_venv()` 为真、**直接跳过 re-exec 那段代码**，所以从没暴露这个 bug。
**必须用系统 python 测**（`C:/Users/Justine/AppData/Local/Programs/Python/Python311/python.exe start.py`），
这才是用户 `python start.py` 的真实场景。同理 `start.bat` 要用 `cmd //c start.bat` 测。

**Windows 上含空格/中文路径的通用原则**：
- 不要用 `os.execv` / `os.execve`，用 `subprocess` 传 list
- `.bat` 里用 `%~dp0` 而不是硬编码路径
- 写脚本时始终用绝对路径 + 引号

## 第五轮：业务模型重构（聊天式工作区）

### 用户指出的根本错误
我把业务理解错了。**正确模型**：像网页版 LLM 一样的聊天式工作区 ——
**一个 chat = 一个求职场景 = 恰好一份简历**。
错误模型是「粘贴一大段 → 切成 N 个岗位 → 批量建 N 个任务 → N 份简历」。
用户库里的 chat #52–#57 标题是 `Responsibilities`/`Requirements`/`Working Terms`，
就是他那条 JD 被按空行切成 4 块的现场证据。

### 三条与用户确认的设计约束
1. **资料**：全局资料库为主 + **per-chat 整体快照**（chat 内可改，不影响全局与其他 chat，可重置回全局）
2. **内容边界**：简历**必须覆盖岗位每一条要求**，同时产出**覆盖清单**标注依据：
   `grounded`（真实经历，须有 evidence_ref）/ `capability`（仅能力层面表述）
   —— 用措辞达成覆盖，但**不编造可证伪的具体事实**（公司名/年限/项目名/数字/学历）
3. **页面**：`01 资料 / 02 工作区 / 03 简历`，删掉「岗位」与「任务」

### 关键设计决策（架构师产出，我拍板）
- **`JobTask` → `Chat` 重命名，不新建表**：调度器全以 task id 为键，重命名是机械替换，
  能 100% 复用已被 160+ 项回归验证的并发/重试/取消/重启恢复逻辑。新建表 = 重写调度器，风险过高。
- **`Resume` 关联收敛为单向**（只留 `Resume.chat_id`）：之前"删任务要先解绑"那套绕外键代码，根源就是双向引用。
- **资料用整体快照而非增量 diff**：diff 合并语义反直觉；chat 是冻结的工作上下文；
  「重置回全局」退化为一次深拷贝。
- **`/api/tasks*` 保留为 deprecated 兼容层**：让 5 个 HTTP 级测试继续当安全网 ——
  它们覆盖的恰是本次**不重构**的部分（调度器/重试/取消/渲染/净化）。
- **重新生成 = 覆盖**（契合一 chat 一简历），但记进 `EditLog(instruction="重新生成")`，
  这样现有的「回退上一版」按钮能救回来，零新增字段。
- 迁移：幂等脚本 `app/migrate.py`，**不删库**。SQLite 的 `create_all` 不会改已存在表结构，
  要用 `PRAGMA table_info` 探测 + `ALTER TABLE`/重建表。

### 顺带修的真 bug：`llm_max_tokens` 太小
`config.py` 默认 4096，而 `SYSTEM_AI_EDIT` 要模型返回**整份简历 HTML**（约 9KB）→ 输出被截断
→ 报「无法解析 JSON」这种误导性错误。**用户配了真实 DeepSeek key，一用就踩到。**
修：默认提到 8192 + 检测 `finish_reason == "length"` 抛可读的「输出被截断」错误 + 设置页可调。
实测：用真实 key 跑 AI 编辑，12.8s 成功（修复前必失败）。

### 独立验证结果
我用真实 DeepSeek key 跑了完整聊天流程：**28/28 全通过**。
- 生成耗时 33.3s，产出 10676 字符简历
- 覆盖清单 4 条（grounded 1 / capability 3 / uncovered 0），grounded 项都有 evidence_ref
- Employer questions 单独解析出 2 条，**未混入简历正文**
- 快照隔离正确（改 chat 快照不影响全局）
- 再生成仍只有 1 份简历 + 记了 EditLog
- 删除对话级联删简历

工程侧：`regression.py` **209/0**、`smoke` ✅、`xss_probe` 12/0、`progress_probe` ✅、
`e2e_verify` 41/0、新增 `chat_e2e.py` 15/0（0 控制台错误）、`ui_check.py` 重写后 13/13。

### 注意：用户库里有真实 API Key
`data/app.db` 的 `llm_api_key` 是真实 DeepSeek key。**跑测试必须用隔离 DB（剥掉 `llm_*` 设置）走降级链路**，
不要往共享库写测试数据、也不要大量消耗用户额度。

## 第六轮：测试脚本缺陷（同日收尾）

最终全套测试暴露一个真缺陷：**`regression.py` 在干净库上跑不起来**。

```
DATABASE_URL="sqlite:///./data/_iso_reg.db" python backend/tests/regression.py
→ sqlite3.OperationalError: no such table: appsetting
```

**根因**：`main()` 先读 `worker_count` 护栏，之后才进 `with TestClient(app)` ——
而建表 `init_db()` 是 TestClient 的 lifespan 触发的，**顺序反了**。

**这一条同时解释了两个之前想不通的现象**：
1. **测试会往用户真实库里写数据**（chat #58/#59 就是这么进去的）—— 因为测试脚本**只能**打共享库
2. **偶发失败** —— 测试进程与 8000 端口开发服务器**共用同一个 SQLite 文件**，写入争抢时偶发失败
   （我遇到一次 `208 通过 / 1 失败`，重跑 5 次都 209/0）

## 第十轮：浅色模式（10/11 下午）

用户要求：设置里加颜色模式，浅色沿用当前设计语言（方角、青色信号、1px 细线）。

### 实现
- **主题作用域**：`document.documentElement.setAttribute('data-theme', 'light'|'dark')`，
  CSS 用 `:root[data-theme="light"]` 只覆盖颜色 token，几何/字体/动效沿用深色。
- **持久化**：localStorage（`arg.theme`：dark/light/auto），纯前端偏好不进后端。
  `index.html` `<head>` 里有**早期同步脚本**在首帧前应用，避免「先闪深色再切浅色」。
- **切换立即生效**：设置弹窗下拉 change 即 applyTheme，所见即所得，不依赖保存按钮。
  "跟随系统"时监听 `matchMedia('(prefers-color-scheme: light)')` 变化。
- 设置弹窗 meta color-scheme 同步 dark/light。

### 必须做的：硬编码颜色 token 化（浅色的前提）
原本 34+ 处硬编码 alpha（白色叠加 18、青色叠加 16、状态色/遮罩 9）在浅色下会失效（白叠白不可见）。
统一替换为语义 token：
- `--tint-soft / --tint-hover / --tint-strong`（白色叠加 → 浅色下改深色叠加）
- `--signal-tint / --signal-tint-strong`
- `--state-tint / --state-glow / --danger-tint`
- `--scrim`（弹窗遮罩）/ `--grid-line`（蓝图底纹）/ `--on-signal`（信号色上的文字色）

**教训：增补 token 时用整块文本锚点容易 assert 失败**（空格/对齐差异），改用「按行定位 `--on-signal:` 后插入」更稳。
**另一个坑**：`if "--state-tint:" not in s` 的检查会被浅色块里的同名 token 骗过（s 全文包含即真），
导致深色 `:root` 漏定义 → 深色下 var 解析失败。**必须按 :root 块边界单独检查**。

### 浅色配色（实测对比度全部达标）
- 底 `--ink #eef1f2`（冷调近白），文字 `--fg #10171a`（15.95）
- **信号色必须加深**：深色 #18d1ff 在浅底上只有 ~2.0；浅色用 `#0a7291`（4.83）
- `--state #546f00`（5.07）、`--muted #5d686d`（5.05）、`--danger #c62828`（4.95）、`--rule 0.20 alpha`
- **简历文档（renderer）不跟随主题**：简历 = 纸张，保持白纸黑字，与 PDF 导出一致。

### 验证
- Playwright 实测：切浅色 → data-theme=light + localStorage 持久化，0 控制台错误
- **对比度断言脚本**：对 hint/细线/主按钮/输入框/正文逐个用计算样式合成半透明前景后算对比度
  （注意：脚本里 parse('#ffffff') 用 `\d+` 解析不了十六进制 → nan 假失败；parse 要同时支持 hex 和 rgb()）

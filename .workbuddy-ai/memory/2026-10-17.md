## 修复内容（start.py / start.bat）
- **双栈探测**：`port_in_use()` 回环语义 host 同时 connect_ex `127.0.0.1` + `::1`；
  `_connect_ok()` 三态 True/False/None（探测不可用降级，不误报不崩，`RESUME_DEBUG=1` 时提示）
- **严格报错**：`busy and is_our_app` → 打开浏览器复用（好行为保留）；否则 `die()` 退出码 1，
  文案含占用者/「不会静默更换端口」的理由（事故教训）/两个出路
- **占用者定位**：`find_port_owner/describe_port_owner`；Windows netstat **端口整数精确匹配**
  （`int(rsplit(":",1)[-1])`，禁 findstr 子串，防 `:15173` 误判）+ tasklist + PowerShell 命令行；
  POSIX lsof/ss//proc 兜底；全部 try/except 降级
- **`--auto-port`**：显式 opt-in 才顺延，输出 `[注意] X 被占用，已顺延到 Y；本服务不在 X 上！`
- **start.bat 真 bug（工程师发现）**：原 `endlocal` 单独一行再 `exit /b %RC%` → RC 被丢弃、
  pause 后 ERRORLEVEL=0 → **bat 永远以 0 退出**。修复：`endlocal & exit /b %RC%`（复合命令解析期展开）。
  另：本仓库 autocrlf=true，start.bat 编辑后须保持 CRLF（批处理对行尾敏感）。
- 新增 `backend/tests/port_guard_check.py`（5 场景：IPv4/IPv6-only 占用/--auto-port/本应用复用/bat 错误路径）

## 需求演进：从「被占即报错」→「默认自动顺延」
用户随后要求参考另一个项目的做法：**自动检测并顺延**。关键洞察：
**问题不在「换端口」本身，而在「静默」和「不校验对方是谁」**。所以安全顺延 = 三件套：
1. **醒目告知**（`[注意] X 被占用，已顺延到 Y；本服务不在 X 上！` + 实际打开地址 + 如何改回严格模式）
2. **身份校验**（`/api/health` 返回 `app: APP_ID`，`is_our_app()` 解析 JSON 校验；
   **伪装服务返回 `{"ok":true}` 但无 app 字段 → 不复用、顺延**，这是「绝不打开别人页面」的硬保证）
3. **`--strict-port` 保留**（被占即报错，供脚本化/CI）；`--auto-port` 降为兼容别名

## 我发现并修掉的第二个「误判空闲」缺陷（3f240a6）
`port_in_use()` 原用 `connect_ex` 探测。对「listen 但从不 accept」的占用者，
**每次探测占对方 backlog 一个槽且不释放**，满了之后 connect 被 RST → 误判空闲：
```
listen(1) 不 accept：port_in_use x3 = [True, False, False]   ← 缺陷
bind 尝试 = 失败 WinError 10048                              ← 端口确实被占
```
后果链：`main()` 第 1 次判 busy → `find_port()` 第 2 次探测误判 False → **「顺延到原端口」**
→ uvicorn bind 失败 → 用户看到自相矛盾输出。
**修法：connect 快速路径 + bind 兜底**（`_probe_occupied` / `_bind_ok`，**不设 SO_REUSEADDR**，
Windows 设了会允许绑到已占端口；`EADDRINUSE`/`WinError 10048` = 占用，其他异常 = 探测不可用降级）。
修复后 `[True, True, True]`，幂等。

**这是「误判端口空闲」的第二种形态**：① IPv6 盲区（只探 127.0.0.1）② backlog 满（connect 被拒）。
教训：**任何单一探测手段都有盲点，「我能不能 bind」才是「我能不能起来」的真判据**。

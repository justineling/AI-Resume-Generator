# 2026-10-19 桌面安装包（Tauri 2 + Python sidecar）

## 需求
用户的目标用户**没有 Python**，要一个 exe 安装包。参考另一个项目（Forest Gap）的
`构建安装包.bat`：阶段化 + 心跳 + 旧产物挪走避免误报 + 失败归因。**要求在新分支**。

分支：`feature/desktop-installer`（从 main `2cfbf1e` 切出）

## 架构（已定，别推翻）
```
安装包(NSIS) → ai-resume-generator-desktop.exe (Tauri 2 窗口)
  └ spawn → resume-server.exe (PyInstaller onefile, FastAPI+uvicorn)
       └ --port 0 自选端口 → stdout 打印 `APP_READY <port>` + 写 {data}/port.txt
  └ Rust 轮询 http://127.0.0.1:<port>/api/health，**强校验 app == "ai-resume-generator"**
      → 通过才 navigate 到该地址；失败把占位页替换成可读错误
  └ 退出 kill sidecar
```
**为什么窗口加载 http://127.0.0.1:<port>**：前端全用绝对路径 `/api`、`/static`，
同源加载后**零改造复用现有 SPA**。动态端口 + 身份校验 = 不会打开别人的页面（沿用端口守卫底座）。

## 关键前置改造（必须，否则用户数据每次重启都丢）
`backend/app/config.py` 的 `DATA_DIR = PROJECT_ROOT / "data"`（import 时 mkdir）。
PyInstaller onefile 下 `PROJECT_ROOT` 是 `_MEIPASS`（**每次启动都不同的临时目录**）。
→ 新增 `APP_DATA_DIR` 环境变量覆盖；未设且 `sys.frozen` 时落 `%LOCALAPPDATA%\AIResumeGenerator\data`；
其他情况维持 `PROJECT_ROOT/data`（**非打包场景行为必须完全不变**，10 个测试套件不能受影响）。

## 产物与文件
```
desktop/            package.json / dist/index.html(占位页源码) / src-tauri/{main.rs(426), tauri.conf.json, capabilities/default.json, icons/}
packaging/          server_entry.py(265) / resume-server.spec(123) / make_icon.py / tauri_build.py(235)
构建安装包.bat      阶段 1-5：查环境 → 装依赖/生成图标 → PyInstaller → tauri build(心跳) → 报产物
```
`packaging/tauri_build.py` 存在的原因（踩坑）：本机同时设 `HTTPS_PROXY` 与 `https_proxy`，
Windows 环境块大小写不敏感 → PowerShell `Start-Process` 重建环境字典时抛
「Item has already been added. Key: 'HTTPS_PROXY'」。Python subprocess 不做重建，故绕开。

## 发现的真 bug（未修完，已派回）
**窗口从未加载真实应用**，停在占位页。证据：
- sidecar 的端口上**只有 LISTEN，无任何 ESTABLISHED**；
- **msedgewebview2 全部进程零 TCP 连接**；
- 而前端 `boot()`(app.js:638) → `connectEvents()`(api.js:88) 会建 `ws://${location.host}/ws/tasks`
  **持久连接** → 页面加载了必然有连接。零连接 = `window.navigate()` 未生效。
另观察到一次 `resume-server` 有**两个 PID**（GUI 被强杀时 RunEvent::Exit 不触发 → sidecar 变孤儿）。

**教训（重要）**：`install2.log` 报 PASS 但它只验了「进程活着 + health 200」，
**没验「窗口里到底是什么页面」**。验收标准必须是「能证明用户看到的是应用」，不是「后端起来了」。
测量手段也踩坑：`WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` 远程调试端口在本机不生效
（连 9333 被拒），改用 netstat 查 webview2 的连接才是可靠证据。

## 环境事实
- 本机工具链齐全：node 22.22 / npm 10.9 / rustc 1.99 / cargo 1.99
- 构建耗时：Rust 首次 10-20 分钟（必须有心跳，批处理里否则像卡死）
- 安装测试用 `D:\_aitest`（不要放项目内）
- **Windows 上 `wmic` 已移除**（`FileNotFoundError [WinError 2]`）→ 枚举进程用 **ctypes + CreateToolhelp32Snapshot**
  （`PROCESSENTRY32W`），不要依赖 wmic / PowerShell（PS 的 Add-Type 会被安全策略拦、Start-Process 因
  `HTTPS_PROXY`+`https_proxy` 大小写冲突而抛异常）。
- **本机用户级 `CARGO_TARGET_DIR = D:\forest-gap-tools\rust\target`**（与 Forest Gap 项目共用）。
  手动跑 `npm run tauri build` 会把产物写进**别人的项目目录**；`packaging/tauri_build.py` 里
  已用 `env["CARGO_TARGET_DIR"] = <cwd>/src-tauri/target` 钉死，**必须通过脚本构建**，别手动跑。

## 关于「窗口白屏」的最终结论（我自己的测试方法造成的）
用户手动双击 exe **一直能正常启动**。我这边 FAIL 的原因是：
我用脚本 `terminate()`/`taskkill` 强杀 GUI → `msedgewebview2.exe` 变孤儿，继续占用
`%LOCALAPPDATA%\com.justine.ai-resume-generator\EBWebView` → 下次启动 WebView2 初始化失败 →
Tauri 给个纯白 Surface 且不报错。
⚠️ `taskkill /F /IM resume-server.exe` **只杀 sidecar，不杀 webview2**，所以 profile 会一直锁着。
→ 清理 `EBWebView` 目录后一切正常（`webview2 子进程=1`、端口 `ESTABLISHED=2`、health 200）。
**教训**：自动化测试不要强杀 GUI；如需清理，必须同时 `taskkill /F /IM msedgewebview2.exe`。
「进程活着 + health 200」不能证明页面渲染了 —— 但那是我测试环境的假象，不是产品缺陷。

## 默认安装目录：`D:\AI Resume Generator`（关键机制）
Tauri NSIS 模板的两层行为：
1. `installMode: currentUser` → 默认 `$LOCALAPPDATA\<产品名>`；
2. **`RestorePreviousInstallLocation` 会从注册表读回上一次的安装路径**
   键：`HKCU\Software\justine\<产品名>`（MANUKEY+PRODUCTNAME），值名是空串。
   → 只要有人用 `/D=D:\_aitest\app` 装过一次，**之后不带参数也会沿用该目录**。
   这就是用户看到「默认还是 D:\_aitest\app」的真因（我早期测试用 /D= 装的）。
   清理方法：删掉该键（`winreg.DeleteKey`）。

**改成默认 D 盘的做法**（`packaging/repack_nsis.py`，已接入 `构建安装包.bat` 阶段 4.5）：
- Tauri 生成的 `target/release/nsis/<arch>/installer.nsi` 是**完全展开**的（File 指令都是绝对路径），
  只替换 `StrCpy $INSTDIR "$LOCALAPPDATA\${PRODUCTNAME}"` → `StrCpy $INSTDIR "D:\${PRODUCTNAME}"`；
- 用 tauri 缓存的 `%LOCALAPPDATA%\tauri\NSIS\makensis.exe` 在同一目录重编译；
- 用新产物覆盖 `bundle/nsis/*.exe`（旧包先备份，makensis 失败则保留原包）。
- 不维护整份 32KB 模板，Tauri 升级也不会失效。
**踩坑**：在 Python 里写 `"D:\\${PRODUCTNAME}"` 经过多层转义会变成 `D://${PRODUCTNAME}`（NSIS 能认但
`FileExists "D://*.*"` 不可靠）。**用 `BS = chr(92)` 拼接反斜杠**，彻底绕开转义。

**验收**：清注册表记忆 + 删目录（模拟全新用户）→ `/S` 静默安装 → 落在 `D:\AI Resume Generator`，
`C:\Users\...\Local\AI Resume Generator` 未被创建。

## 窗口尺寸
`tauri.conf.json` 加 `"maximized": true`（**不要用 fullscreen** —— 会隐藏标题栏导致无法关闭）。
重建窗口（`rebuild_window`）也要沿用 `is_maximized()` 状态并显式 `window.maximize()` 兜底，
否则导航到应用后窗口会退回 1280x900。

## 真因（最终定位）：`navigate()` 投递成功但不生效
`WebviewWindow::navigate()` 返回 Ok，但窗口被钉在 `http://tauri.localhost/`；
连页面自己 `location.replace()` 也不生效。修复（`ee0a66e`）：
**`WebviewWindowBuilder::new(.., WebviewUrl::External(url))` 重建窗口**（初始 URL 即目标，绕开运行时导航），
再用 `window.url()` 回读校验。另修了一个自埋 bug：先 `mark_ready()` 再 `navigate()` 会让失败被
`is_ready()` 早退吞掉 → **静默无提示**。顺序改为「导航成功后才 mark_ready」。

## 第二个真缺陷：WebView2 profile 被锁 → 白屏且无任何提示
之前强杀 GUI 后 `msedgewebview2.exe` 变孤儿，继续占用
`%LOCALAPPDATA%\com.justine.ai-resume-generator\EBWebView` → 下次启动 WebView2 初始化失败 →
Tauri 给个空白 Surface，**不报错**；而 `launch.log` 还显示「导航成功（rebuild）」——
**URL 变了 ≠ 渲染了**，日志在说谎。
**关键教训**：`taskkill /F /IM resume-server.exe` 只杀 sidecar，**不杀 webview2**，
所以 profile 会一直锁着，问题在环境里持续存在（我一度误判为「修复无效」）。

## 验收方法论（本轮最有价值的沉淀）
「进程活着 + health 200」**不能证明用户看到的是应用**。必须三层证据：
1. **webview2 是本进程的子进程**（ctypes 枚举 ParentProcessId）；
2. **sidecar 端口上有 ESTABLISHED 连接**（前端 `boot()` 必建 `/ws/tasks` 长连接，零连接=没加载）；
3. **页面自报**：`window.eval("document.title")` 校验（应用页 `AI RESUME GENERATOR / …`
   vs 占位页 `… 正在启动`）——这是唯一能区分「渲染了」与「URL 对了但白屏」的手段。
不可靠手段（已踩）：`PrintWindow` 抓 WebView2 常返回纯白；整屏截图无法定位到窗口；
`WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` 远程调试端口在本机不生效（9333 被拒）。

清理 profile 后实测正常：
```
t+ 2s 子进程 webview2=1；t+ 4s 端口=63792 ESTABLISHED=2（63792↔63795）
health = 200 {"ok":true,"app":"ai-resume-generator"}
```
